# Subscription UI handoff

This checkout contains display and navigation only. The landing page links to public `/plans`, which shows a free “اسأل صح” tier and $10 for one year of all available games. Clicking a plan stores a validated `free` or `annual` navigation intent in tab-scoped `sessionStorage`, with an in-memory fallback if storage is blocked. It survives signup/login/verification and `/setup`, then is consumed: free goes to `/app` game selection, annual to `/subscription/summary`. Login without an intent goes to `/app`. Free routing to `/app` is temporary until server-side subscription access is implemented. The intent is not a subscription or entitlement. The summary's payment button is disabled; it creates no order. Both games remain available under their existing authentication/profile checks.

`/subscription` currently renders `SubscriptionDetails` with `null` and shows a plan discovery card, without assigning a tier to the account. `src/features/subscription/model.ts` defines the future display contract: a server-confirmed free tier, or an annual tier with `pending`, `active`, `failed`, or `expired` status and an optional expiry timestamp. These states are presentation only. No browser value can prove entitlement.

For integration, add an authenticated server read scoped to the session owner, then pass its verified snapshot to `SubscriptionDetails`. Create checkout only on the server for the signed-in account, confirm the provider callback server-side, and derive game entitlement from trusted payment records and expiry there. Enforce access in backend policies/functions before adding client route gates. Define the confirmed merchant configuration, one-time versus recurring billing, refunds, and coverage of future games before implementation. Never place Fawaterak credentials in `VITE_` variables or use `localStorage` for paid access.
