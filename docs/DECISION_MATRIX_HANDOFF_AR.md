# تسليم دمج مصفوفة القرار

## حالة الدمج — 2026-10-26

استُبدل تنفيذ `public/decision-matrix/` بحزمة `decision-matrix-story-preview-main.zip` التي أرفقها المستخدم. مصدر اللعبة داخلها هو `dist/`، ويضم القضية الأولى والثانية، الملفات الصوتية الجديدة بصيغة WAV، وملفات الواجهة والأصول. ملفات `test-puzzle1.html` إلى `test-puzzle3.html` وحدها لم تُنشر؛ فهي صفحات اختبار مستقلة وليست ضمن مراجع تشغيل اللعبة. بقيت بنية المسارات النسبية كما هي.

يمكن الوصول إلى أحدث `HEAD` لمستودع المصدر، وهو `eae027d4b81894cc2bce55496390dd9d58b381d5` بتاريخ 2026-10-26، لكن ملفات `dist/` في ذلك الإصدار لا تطابق الأرشيف المرفق. استُخدم الأرشيف بوصفه المصدر المعتمد وفق طلب الاستبدال.

يحافظ التطبيق على مفتاح المنصة الحالي لكل حساب: `theanalyst.decision-matrix.v1.<encoded-user-id>`، وتفضيلات منفصلة بالطريقة نفسها. قبل أول كتابة بالتنسيق الجديد، تُنسخ البايتات النصية للحفظ السابق إلى `<save-key>.pre-replacement` دون حذفها. تقبل أداة الترحيل بيانات الحالات السابقة المتوافقة؛ الحالة القديمة للقضية الثالثة (6×6) تُطوى إلى نهاية اللعبة الجديدة ذات القضيتين، لأن القضية الثالثة لم تعد ضمن الإصدار الجديد. الحفظ محلي في المتصفح فقط، ولا يتزامن بين الأجهزة أو المتصفحات.

ما زال مسار `/games/decision-matrix` محميًا بـ`RequireProfile` و`GameGate`، ويحمل iframe معرّف المستخدم عبر `window.name`. لم تتغير بوابة الوصول أو مصفوفة الاشتراك أو المصادقة. لا يلزم ترحيل قاعدة بيانات.

المسار ملفوف بـ`RequireProfile` و`GameGate` مثل بقية الألعاب، وزر الرجوع إلى `/app` موجود في شريط مستقل أعلى مساحة اللعب حتى لا يحجب أي تحكم. بقيت بطاقة اللعبة الخامسة وصورة الغلاف.

## حدود الوصول والأصول

لا توجد قيود اشتراك جديدة؛ تظل اللعبة متاحة للمستخدم المسجل دخوله الذي أكمل ملفه، وفق حدود الوصول الحالية للمنصة. حماية React لا تحمي روابط الملفات الثابتة تحت `/decision-matrix/`، ويمكن طلب HTML وJavaScript والصور والصوت مباشرة. لا تُعامل هذه الملفات كأسرار أو كحد وصول تجاري؛ يلزم تخطيط منفصل لحماية الأصول إذا أصبحت entitlement شرطًا مستقبلًا.

## التحقق

- حزمة المصدر: شُغّل `node build-deliverables.cjs` ثم `npm test` من جذر الأرشيف. نجحت اختبارات الحلول الفريدة للقضيتين، الحسابات والانتقالات، الصوت، تسلسل الاجتماع، المشهد، واللوحات.
- تحقق المنصة: `tests/decision-matrix-integration.test.mjs` يختبر اختلاف مفاتيح الحفظ والتفضيلات بين المستخدمين، حفظ نسخة من البيانات القديمة قبل الكتابة، وبقاء فهرس اللعبة والمسار المحمي وملكية iframe.
- المتصفح عبر خادم معاينة محلي: ظهر مدخل اللعبة، وتم الحوار وتسليم ملف CRM. أكمل اختبار Playwright القضيتين عبر عناصر الواجهة، وصل إلى ملخص النهاية، ثم أعاد التشغيل. فحص التحديث كذلك الاستئناف بعد التحديث، عزل مستخدم ثانٍ، عرض 390×844 و1365×900، وأخطاء المتصفح واستجابات الأصول؛ لم تظهر أخطاء JavaScript أو 404 أو زيادة أفقية. اختُبر المسار الثابت مباشرة؛ لم يُسجّل دخول حقيقي ولم يُختبر سلوك المصادقة على خدمة حية.
- فحوص المنصة: `npx tsc -p tsconfig.app.json --noEmit` و`npx tsc -p tsconfig.node.json --noEmit` والبناء الإنتاجي نجحت. يعرض البناء تحذير chunk كبير قائمًا. `npm run lint` ما زال يفشل بأخطاء في ملفات غير مرتبطة بهذه اللعبة، منها `AuthContext.tsx` و`phone-auth` واختبارات Reward Decision.

## إعادة الاختبار

من جذر المستودع:

```sh
node --test tests/decision-matrix-integration.test.mjs
npx tsc -p tsconfig.app.json --noEmit
npx tsc -p tsconfig.node.json --noEmit
npm run build
```
